# os — OS 자산 변경 게이트

이 OS는 OS.md(청사진) ↔ 스킬 ↔ 서브에이전트 ↔ 컨텍스트 ↔ 산출물(learnings)이 서로 맞물려 있다. 하나를 고치면 그걸 참조하는 다른 곳이 조용히 어긋난다. 이 스킬은 OS 자산을 고칠 때 **정합성·작성규칙 점검을 게이트로 태워** 그 드리프트를 닫는다. 게이트 자체가 목적이 아니라 **align 유지**가 목적이다.

## 대상 (OS 자산)
- `.claude/` 전체 (스킬·서브에이전트·컨텍스트·훅·settings)
- `OS.md`, `CLAUDE.md`
- `learnings/`

## 언제 쓰나
- 위 자산을 **의미 있게** 바꿀 때: 스킬·에이전트 추가/수정, 컨텍스트 규칙 변경, 파이프라인 흐름 변경, 훅·settings 변경.
- **안 씀 (그냥 편집):** 오타·한 줄·포맷처럼 참조처에 영향 없는 사소한 편집. 편집 뒤 리마인더가 떠도, 사소하면 건너뛴다.

애매하면: 이 편집이 **다른 자산의 전제를 바꾸나?** 바꾸면 태운다.

## 흐름

```
편집 요청
 → 의도 확인   무엇을 왜 바꾸나 · 어느 자산이 영향받나 한 줄로
 → 편집        요청된 변경 적용 (여러 자산이 물리면 함께 바꿔 반쪽 상태 금지)
 → 정합성      sync — 바뀐 자산 ↔ 참조처 드리프트 전수 점검 (리포트만)
 → 작성규칙    lint — 바뀐 스킬·에이전트·컨텍스트가 작성 규칙 지켰나 점검 (리포트만)
 → 기록        구조를 바꿨으면 retrospective(os-improvement) 제안
 → 승인        바뀐 파일 + 두 점검의 수정안을 한 화면에 요약 → 승인 한 번으로 함께 반영 (유일한 수동 게이트)
```

## 단계 지침

### 의도 확인
무엇을·왜 바꾸는지, 그 변경이 **어느 자산을 참조/의존하는지** 한 줄로 짚는다(예: 설계도 형식을 바꾸면 그 생산자·소비자가 함께 영향받는다). 사소하면 여기서 멈추고 그냥 편집한다 — 게이트 불필요.

### 편집
요청된 변경을 적용한다. 하나를 바꿔 다른 곳의 전제가 깨지면 **같은 편집에서 함께** 맞춰 반쪽 상태를 남기지 않는다.

### 정합성 — sync
`sync`를 돌려 바뀐 자산과 그 참조처의 드리프트를 전수로 잡는다. sync는 리포트만 한다 — 발견한 수정안은 아래 승인 단계로 모은다.

### 작성규칙 — lint
`lint`를 돌려 바뀐 스킬·에이전트·컨텍스트가 작성 규칙을 지켰는지 본다. lint도 리포트만 한다 — 위반의 수정안은 아래 승인 단계로 모은다.

### 기록 — retrospective
스킬·서브에이전트·파이프라인 구조 자체를 바꿨으면 `retrospective`(os-improvement)를 **제안**한다(강제 아님). 내용만 소소하게 다듬었으면 건너뛴다.

### 승인
바뀐 파일과 sync·lint가 낸 수정안을 한 화면에 요약해 승인을 요청한다. 이 흐름의 유일한 게이트다 — 승인 한 번으로 편집·sync·lint 수정을 함께 반영한다. 사람이 판단한다.

## 원칙
- **게이트지 강제가 아니다.** 편집을 물리적으로 막지 않는다 — 상기시키되, 사소한 편집은 건너뛴다.
- **정합성이 존재 이유.** "고쳤는데 참조처를 안 맞춰 생기는 드리프트"를 닫으려고 만든 것이다.
- **재구현하지 않는다.** 점검·기록은 sync·lint·retrospective를 그대로 부른다 — 규칙이 한 곳에 있게.
